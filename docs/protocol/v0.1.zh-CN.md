# TorchMap 实验协议 v0.1 · 草案

状态：可运行草案。协议标识为 `tensormap/0.1`；它独立于软件版本，也独立于地图文件的 `schemaVersion: 1`。本文的“必须”指本版写入方与读取方的约定。示例全部虚构。

## 一张卡到底代表什么

一张卡代表一个有意比较的模型版本。相同配方换种子，创建新的训练 run；从自己的 checkpoint 恢复，沿用 run 并开启下一个 attempt；改变配方后续训，创建子版本和新的 run，并引用父版的具体 checkpoint。只继承方法而从零训练时，仅建立地图连线。**继承方法不等于加载上游权重。**

| 对象            | 身份及关系                                      | 记录                                                                                            |
| --------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 项目            | 隔离命名空间；所有引用限于同一项目              | 地图、运行、附件；可整体归档                                                                    |
| 版本            | 地图 node.id；允许多个上游；有向无环            | 日期、标题、主要改动、可选的配置说明、画布行位                                                  |
| 运行 run        | runId 唯一，属于一个版本；kind 为 train 或 eval | 该次使用的配置、初始或受测 checkpoint；评测还必须指明 dataset、protocolId                       |
| 尝试 attempt    | (runId, attempt)，从 1 连续递增                 | 一次实际执行；重启不会抹掉旧曲线                                                                |
| 权重 checkpoint | checkpointId 唯一，只有训练运行可以登记         | 产生它的 run、attempt、step、weights 和 uri。raw 与 ema 即使步数相同也用不同 ID，不复制权重文件 |
| 附件            | 一个版本，可选绑定该版本的某次 run              | 手工提供的 Markdown、PNG 或 JPEG；文件名、类型和内容摘要                                        |

`protocolId` 是评测方法的版本，例如 `macro-v1`。改变标签范围、时间容差、聚合方式或数据切分应另取标识。建议给 dataset 使用固定版本 ID，给 config 记录 seed、代码版本和主要参数。键名、单位和数值刻度由项目约定，例如统一使用 `accuracy_fraction`，不要把 0.9 与 90 混入同一序列。

## 唯一写入入口

默认服务地址是 http://127.0.0.1:18770 。通过 HTTP 或 CLI 写入，所有写操作由一个本地服务串行处理。查询参数 `project` 省略时选 default，其他项目使用服务生成的 UUID。不得直接往正在运行的服务的数据文件追加内容。

`POST /api/events?project=<id>` 接收一个 JSON 对象。公共字段是 `protocol`、`id` 和 `type`。事件、运行及权重 ID 区分大小写，限 1–96 个 ASCII 字母、数字、连字符、下划线，首位为字母或数字。服务写入 UTC 接收时间 `at`。重试应重发同一 ID 和同一载荷：内容相同返回 duplicate，内容不同则拒绝。每次运行只有一个生命周期写入方，多卡训练建议 rank 0 上报。指标名可以包含斜线。

| type             | 主要载荷                                         | 规则                                                                                                                 |
| ---------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| run.created      | runId, versionId, kind，可选 config              | train 可用 checkpointId 表示同版或直接上游的初始权重；eval 必须提供同版 checkpointId、dataset、protocolId            |
| attempt.started  | runId, attempt；可选 resumeFrom                  | 排队可启动；失败或明确停止后可重试。续训的 resumeFrom 必须是本 run 已登记的权重。不填表示从本 run 原始初始化重新执行 |
| heartbeat        | runId, attempt，可选 step                        | 只接受当前运行中的 attempt；建议每 30 秒上报                                                                         |
| metric           | runId, attempt, step, name, value                | step 是非负整数，value 是有限数；保留原始步数及 attempt，不拼接成虚构的连续曲线                                      |
| checkpoint.saved | runId, attempt, checkpointId, step, weights, uri | 在权重**写完后**登记。uri 是生产方提供的位置，服务不访问或验证该文件                                                 |
| attempt.ended    | runId, attempt, status，可选 reason              | status 为 succeeded、failed 或 stopped；成功为该 run 终态                                                            |
| artifact.added   | 由附件接口生成，不直接提交                       | 同一个二进制内容按 SHA-256 存储；文件引用绑定到具体版本或 run                                                        |

例如，版本 `baseline`、训练 `train-a` 及其第一次 attempt 已登记后，以下两条消息将一次验证明确关联到一份权重：

```jsonl
{"protocol":"tensormap/0.1","id":"save-40k","type":"checkpoint.saved","runId":"train-a","attempt":1,"checkpointId":"a-40k-ema","step":40000,"weights":"ema","uri":"weights/a-40000-ema.pt"}
{"protocol":"tensormap/0.1","id":"eval-40k","type":"run.created","runId":"eval-a-40k","versionId":"baseline","kind":"eval","checkpointId":"a-40k-ema","dataset":"heldout-v1","protocolId":"macro-v1"}
```

评测过程可用 heartbeat.step 上报已处理记录数。评测完成前发布聚合指标，每个指标以该成功 attempt 最后一次同名采样为最终值。图上横坐标取**被评权重的训练步**，不用评测自身步数。训练曲线按 run 与 attempt 分线；评测按数据集、评测口径、权重类型、指标分组。比较上游时保持这些键一致。相同权重的独立重复评测不自动取平均。

## 进程边界

状态从 queued 到 running，再到 succeeded / failed / stopped。running 超过 120 秒没有心跳、指标或状态更新，网页显示“失联，未确认退出”。断联本身不触发失败、终止或重启。外部训练可以自主发事件，TorchMap 不按 PID 操作外部进程。本地 `exec` 可启动并监督一个直接子进程，按退出码登记结果，Ctrl+C 请求停止。此接口不承担跨主机调度、进程树清理，也不把一份 JSON 当 shell 脚本执行。

## 文件、迁移与恢复

默认目录为 `data/tensormap/`，可用 `TENSORMAP_HOME` 指定独立工作区。一个工作区只允许一个服务写入。

```text
workspace.json                 协议标识与创建时间
projects/<project-id>/
  map.json                     可编辑的版本 DAG；拖卡仅修改此文件
  map.backup.json              上一次地图保存
  events.jsonl                 每行一个已提交事件，含指标；只追加
  assets/<sha256>.<ext>        手工附件原件
archive/<project-id>/          整个归档项目
```

当前参考实现用一份项目事件流保证元数据、checkpoint 与指标之间的写入顺序，不让多个进程竞争写文件。门户将运行曲线按游标分页，每页最多 1000 条。服务重启时回放日志；遇到无换行的残尾，先留存 partial 文件再截到上一完整行；完整行损坏则报错，不跳过。服务确认表示文件写操作完成，不承诺断电后的持久性。当前实现将历史索引载入内存，不宣称已支持无限规模或高频张量记录。

首次打开新工作区，复制现有 Experiment-Map 的活动项目和默认地图；若没有旧地图，则使用虚构样例。迁移不改旧文件、不推测人工指标的 checkpoint，也不会将人工卡片状态作为运行事实。已有 TorchMap 工作区不重复迁移。网页的 JSON 导入/导出仅交换地图；完整备份需在停止写入后复制整个工作区。删除带运行或附件的版本会被拒绝，可归档整个项目。

## 读取、附件与差错

- GET /api/projects、GET /api/project：项目列表、当前地图。POST /api/projects 新建；POST /api/versions 使用 {node,parents} 加卡；PUT /api/project 支持 X-Map-Revision 防止陈旧页面覆盖新图。
- GET /api/snapshot：运行状态、权重和附件索引。GET /api/metrics?run=<runId>&after=0 返回 items、next、more；after 是该运行的指标条数游标。
- POST /api/artifacts：protocol、id、versionId、可选 runId、name、format、base64 编码的 content。单个附件上限 4 MiB，只支持 md、png、jpg。GET /api/asset?id=<eventId> 读取原件；Markdown 作为 UTF-8 文本提供，不执行 HTML。权重和生产数据都不应当作附件。
- 所有接口对默认项目以外的访问均加 project 参数。成功返回 JSON（原件接口除外），失败返回非 2xx 和 {error}。工作区只面向受信任的本机用户；远程主机可使用 SSH 隧道，没有公网鉴权。
- skill、CLI 和网页使用同一写入协议。人可以上传已有记录；**AI 自动撰写、修改实验日志不属于 v0.1**。跨主机队列、TensorBoard 日志导入也是后续扩展，不是现版本的功能承诺。

## 验收一个接入方

同一份原始权重派生两个配置时应能追到同一来源；同一步的 raw 和 EMA 可分别评测；重复发送相同事件不应多一个点；旧 attempt 的迟到指标不能进入新 attempt；服务断开再连接能恢复图和曲线。用第二个项目采用不同指标名再走一遍，无需修改核心协议。
